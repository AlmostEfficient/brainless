# Brainless Agent Guide

Brainless is a SwiftUI iOS app for personalized workouts generated by the backend at `https://nexus.raza.run/v1`. The canonical API contract is `/Users/raza/Projects/nexus/docs/api/workout-generation.md`; read it before changing generation, exercise identity, assets or validation.

## Invariants

- Exercise selection is unconstrained by ExerciseDB or available media.
- `WorkoutExercise` owns its name, instructions, form cues, dosage and occurrence UUID.
- `asset: ExerciseAsset?` is optional presentation metadata (`catalogID`, `assetID`), never identity or a validation requirement.
- Derive GIF URLs with `ExerciseAssetURLBuilder`; do not store source gifUrl or arbitrary media URLs.
- Resolution is backend-only: conservative exact names and reviewed aliases, never semantic substitution.
- Missing, malformed or failed media must not block a workout, logging or saving.
- There is one `/generate-workout` API and one `WorkoutGenerationService`. `TextWorkoutPlan` adapts the same result to the existing text screen.
- The Swift app calls the backend, never a model provider directly. API tokens belong in `APIClient`.

## Layout

- `Brainless/App/`: dependencies, state, routing and SwiftData record types.
- `Brainless/Models/ProfileModels.swift`: profile and canonical workout models, request/response and JSON coding.
- `Brainless/Models/TextWorkoutModels.swift`: text-screen presentation adapter.
- `Brainless/Persistence/Stores.swift`: main-actor stores using SwiftData JSON blobs.
- `Brainless/Services/`: generation, validation and asset URL construction.
- `Brainless/Features/Home/HomeView.swift`: request construction from persisted context, generation and workout state.
- `Brainless/Features/WorkoutMode/`, `WorkoutPreview/`, `History/`: existing UI consuming workouts.
- Backend: `/Users/raza/Projects/nexus`; follow that repo's `AGENTS.md` and `docs/api/workout-generation.md`.

The Xcode filesystem-synchronized root group discovers Swift files under `Brainless/` automatically. Do not add manual project entries.

## Development

Always use Bun, never npm. Keep changes direct; do not add orchestration, vector databases or provider memory. Do not redesign UI unless asked. Do not revert unrelated user changes. Keep not-medical-advice positioning and conservative handling of user limitations.

Build:

```sh
xcodebuild -project Brainless.xcodeproj -scheme Brainless -destination 'generic/platform=iOS Simulator' build
```

Contract checks (use responses from backend fixture/live smoke checks):

```sh
scripts/check-workout-contract.sh /tmp/brainless-live-workout-1.json
```

Before ending a turn, verify no task-owned build/compiler jobs are still running:

```sh
pgrep -fl 'xcodebuild|swiftc|clang|actool|appintentsmetadataprocessor|ibtool|ibtoold|SourceKitService' || true
```

Do not stop another task's jobs. The missing AppIntents metadata warning is harmless.

## Current limits

The text screen remains a presentation experiment with no completion/history controls. The main workout screen saves the canonical workout including text-only exercises. The existing `AsyncImage` renderer does not add animated GIF playback. Saved pre-release records using the old catalogItem contract are not migrated.

## Local simulator launch

Run the backend with `bunx --no-install wrangler dev --local --ip 127.0.0.1 --port 8787` from the backend directory. Debug builds accept `BRAINLESS_API_BASE_URL` and `BRAINLESS_API_TOKEN` process environment overrides, passed to `simctl launch` with the `SIMCTL_CHILD_` prefix. Release builds ignore these overrides. These are local testing settings, not compatibility behavior; do not hardcode local credentials or change the production URL.

Profile models contain only the current UI's canonical fields. Do not restore primary/secondary goals, duplicate duration or equipment-note fields, old profile metadata, or permissive decoding adapters. Optional asset failure handling remains intentional.
